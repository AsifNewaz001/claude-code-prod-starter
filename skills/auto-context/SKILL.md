# Auto-context — bootstrap PROJECT_CONTEXT.md without asking the user

## Overview

When a noob types `/go add dark mode` in a fresh repo, the plugin's persona agents will refuse to operate without `PROJECT_CONTEXT.md`. This skill removes that friction by auto-generating a minimal but workable `PROJECT_CONTEXT.md` from the repo's existing manifests. The user can fill in TODOs later — but the lifecycle commands (light mode) work immediately.

## When to use

- Called by `/go` when `PROJECT_CONTEXT.md` is missing
- Called by the user manually if they want a starter template generated
- Never used to overwrite an existing `PROJECT_CONTEXT.md`

## When NOT to use

- `PROJECT_CONTEXT.md` already exists — leave it alone, even if incomplete
- The user has explicitly said "I'll fill it in myself"
- The repo has no manifests at all — too little signal; ask the user instead

## Detection rules

Run these checks in order. First match wins for "stack":

| Manifest | Stack inferred | Verify command (best-effort) |
|---|---|---|
| `package.json` with `"next"` | Next.js + Node | `npm test` (or `pnpm test` / `yarn test` matching lockfile) |
| `package.json` with `"react"` | React + Node | `npm test` |
| `package.json` with `"vue"` | Vue + Node | `npm test` |
| `package.json` (other) | Node | `npm test` if `scripts.test` exists; else `npm run lint` |
| `pyproject.toml` | Python | `pytest` if installed; else `python -m pytest` |
| `Cargo.toml` | Rust | `cargo test` |
| `go.mod` | Go | `go test ./...` |
| `Gemfile` | Ruby | `bundle exec rspec` if rspec listed; else `bundle exec rake test` |
| `pom.xml` | Java + Maven | `mvn test` |
| `build.gradle` / `build.gradle.kts` | JVM + Gradle | `./gradlew test` |
| `composer.json` | PHP | `composer test` if defined; else `vendor/bin/phpunit` |
| Multiple manifests | Polyglot | First match above; mention others in "stack" |

For Node projects, also detect lockfile to pick the right runner:
- `pnpm-lock.yaml` → `pnpm`
- `yarn.lock` → `yarn`
- `bun.lockb` → `bun`
- `package-lock.json` (or none) → `npm`

## Generated template

Write this to `PROJECT_CONTEXT.md` at repo root:

```markdown
# PROJECT_CONTEXT.md

> Auto-generated by /go on YYYY-MM-DD. Fill in the TODOs before running /autopilot.

## Stack

<detected stack — 1 line>

Detected from: <manifest file>

## Verify

The single command that proves the codebase is healthy. Must exit 0 if green, non-zero if red.

```
<detected verify command>
```

## Project type

<TODO: one of: SaaS web app | mobile app | library | CLI | data pipeline | other>

## Residency / tenancy

<TODO: where does this run? what data residency rules apply? leave "single-region, no PII" if N/A>

## Brand voice

<TODO: 1-2 sentences on copy/tone. Leave "Standard professional, no exclamation marks" if N/A>

## Hard rules

- Tests ship in the same commit as code.
- No production code without a failing test first.
- No card data on our servers; use payment provider iframes/redirects if applicable.
- <TODO: add project-specific rules>

## File paths

- Tests: <auto-detect: `tests/`, `__tests__/`, `spec/`, `*_test.go`, etc.>
- Build artifacts: <auto-detect from .gitignore>
- Docs: `docs/`

## Cost thresholds

<TODO: what's the dollar limit per /autopilot run before you want to be alerted? Default: $10>
```

Fill in the auto-detectable parts. Leave the `<TODO: ...>` markers where human input is needed.

## Test directory detection

After generating, also check for test directories:
- `tests/` exists → reference it
- `__tests__/` exists → reference it
- `spec/` exists → reference it
- `*_test.go` files → reference Go convention
- None of the above → put `<TODO: tests directory>` and surface in output

## After generation

1. Show the user a 5-line summary of what was filled vs TODO'd:

   ```
   ✓ PROJECT_CONTEXT.md generated.
   ✓ Stack: Next.js + Node (pnpm)
   ✓ Verify: pnpm test
   ⚠ TODOs: project-type, residency, brand-voice, cost-threshold
   → Filling these makes /autopilot work. /go light-mode works without them.
   ```

2. Commit it:

   ```
   git add PROJECT_CONTEXT.md
   git commit -m "chore: bootstrap PROJECT_CONTEXT.md via /go auto-context"
   ```

3. Return control to `/go`.

## Red flags — these thoughts mean STOP

| Thought | Reality |
|---|---|
| "I'll guess at brand voice / residency" | NEVER guess on residency or brand. Mark TODO; let the user own it. |
| "I'll fill in a placeholder verify command" | If you can't detect it from manifests, ask. Wrong verify command silently breaks /test. |
| "I'll overwrite the existing PROJECT_CONTEXT.md" | Never. The user's hand-written context beats your auto-generated one. |
| "I'll add hard rules I think apply" | Only add the universal ones (tests in same commit, TDD, etc.). Project-specific rules → TODO. |

## Verification

- `PROJECT_CONTEXT.md` exists at repo root and is valid Markdown.
- Stack is detected (1 line, sourced from a real manifest).
- Verify command is detected (and runs without error, even if exit code is non-zero).
- TODO markers are present for items that need human input — not faked.
- File is committed in a clean commit.
- The user knows which TODOs they need to fill before `/autopilot` will work.
